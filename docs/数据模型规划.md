# 数据模型规划

本文档确定跨阶段需要稳定的关系与索引方向。阶段 0 的 `users`、`schools`、`campuses` 和阶段 1 的商品交易集合已经定型；后续集合仍在对应阶段开始时细化，避免提前固化未经验证的业务结构。

## 稳定标识与关系

| 数据域 | 计划集合 | 核心关系 |
| --- | --- | --- |
| 用户 | `users` | 以 `_openid` 唯一关联微信身份；关联 `schoolId`、`campusId` |
| 学校 | `schools` | `schoolId` 为稳定业务 ID |
| 校区 | `campuses` | 通过 `schoolId` 归属学校 |
| 出售/求购 | `posts` | 通过 `ownerId` 关联用户，通过 `schoolId`、`campusId` 关联地域；阶段 1 仅启用出售物品 |
| 会话 | `conversations` | 通过 `postId`、`buyerId`、`sellerId` 关联商品与双方，并使用 `uniqueKey` 保证唯一 |
| 消息 | `messages` | 通过 `conversationId` 归属会话，通过 `senderId` 关联发送者 |
| 交易清单 | `transactions` | 关联会话、发起方、确认方和目标信息；保存当前状态及约定时间 |
| 状态记录 | `transaction_events` | 通过 `transactionId` 记录每次状态迁移、操作者与时间 |
| 库存流水 | `inventory_movements` | 通过 `postId`、`transactionId` 记录占用、释放和售出变化 |
| 站内通知 | `notifications` | 通过 `recipientId` 关联接收者，并关联交易或会话上下文 |
| 订阅发送记录 | `subscription_deliveries` | 关联通知与模板，记录发送结果，不作为交易状态依据 |
| 异常凭证 | `disputes` | 关联交易、提交者、原因、说明与云存储图片文件 ID |

用户、帖子、交易等内部关联优先使用数据库记录 `_id`；`schoolId`、`campusId` 等需要跨环境复现的基础数据使用稳定业务 ID。

## 索引方向

| 集合 | 首批索引方向 | 对应阶段 |
| --- | --- | --- |
| `posts` | `status + campusId + availableQuantity + publishedAt + _id`；`ownerId + status + updatedAt` | 阶段 1 |
| `conversations` | 唯一 `uniqueKey`；`buyerId/sellerId + updatedAt` | 阶段 1 |
| `messages` | `conversationId + createdAt + _id`；唯一 `senderId + requestId` | 阶段 1 |
| `transactions` | `buyerId/sellerId + status + updatedAt`；唯一 `conversationId + activeKey` | 阶段 1 |
| `transaction_events` | `transactionId + createdAt` | 阶段 1 |
| `inventory_movements` | `postId + createdAt`；`transactionId` | 阶段 1 |
| `notifications` | `recipientId + readAt + createdAt`；`recipientId + todoStatus + createdAt` | 阶段 3 |
| `subscription_deliveries` | `notificationId`；`status + createdAt` | 阶段 3 |
| `disputes` | `transactionId + createdAt` | 阶段 4 |

具体字段类型、唯一性和组合索引顺序必须在对应阶段依据真实查询语句确认。本规划不授权客户端直接修改库存、交易状态、通知结果或异常结论。

## 阶段 2 关系增量

帖子保存提供/需要方向及物品/服务类型。提供帖owner是seller，需要帖owner是buyer；会话仍由postId+buyerId+sellerId唯一确定。服务和需求订单inventoryManaged=false，不关联商品库存流水。需要帖activeTransactionId由数据库事务限制跨会话同时一笔活跃预约，双方成功后status=completed。具体部署字段与索引见database/README.md。
