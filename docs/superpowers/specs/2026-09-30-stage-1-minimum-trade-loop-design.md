# 阶段 1 设计：最小物品交易闭环

## 1. 阶段目标

阶段 1 围绕“出售物品”交付一条可验证的完整路径：

`发布商品 → 发现商品 → 查看详情 → 文字聊天 → 买家发起交易清单 → 卖家确认并占用库存 → 线下交接 → 双方提交结果 → 完成、失败或异常`

阶段 1 不追求完整 V1 功能。求购、服务、复杂搜索、图片消息、微信订阅通知和平台仲裁均不在本阶段范围内。

## 2. 已确认的产品结构

### 2.1 底部导航

V1 底部导航固定为四项：

1. **发现**：浏览、校区切换和查看出售商品；
2. **发布**：发布新的出售商品；
3. **消息**：查看商品会话、未读消息和交易系统消息；
4. **我的**：维护资料、管理发布和查看交易。

分类与校区筛选归入“发现”；收藏、交易记录和个人设置归入“我的”，不额外占用底部导航。

### 2.2 登录与资料门槛

- “发现”和商品详情允许匿名浏览。
- 发布、消息、联系卖家、发起或处理交易均要求微信身份和完整个人资料。
- 匿名用户触发受保护操作时先建立用户记录；资料不完整时进入完善资料页，完成后返回原操作。
- 卖家不能联系或购买自己的商品。

## 3. 商品发布

### 3.1 发布字段与限制

| 字段 | 规则 |
| --- | --- |
| 标题 | 必填，2～30 个 Unicode 字符 |
| 描述 | 必填，10～1000 个 Unicode 字符 |
| 图片 | 必填，1～6 张；第一张为封面 |
| 分类 | 必填，使用既定一级分类 |
| 参考单价 | 必填，0～999999.99 元，最多两位小数；云端以分为单位存储整数 |
| 库存数量 | 必填，1～99，只允许整数 |
| 新旧程度 | 必填，使用固定五档 |
| 故障说明 | 仅“部分功能异常”时必填，2～200 个 Unicode 字符 |
| 校区 | 必填，默认用户常驻校区，可改为其他北邮校区 |
| 学校 | 固定为北京邮电大学，不在表单中重复选择 |

阶段 1 可选一级分类为：数码、教材书籍、校园出行、生活用品、服饰美妆、运动娱乐、票券卡券、其他。“服务”分类保留给后续阶段，本阶段发布表单不提供该选项。

### 3.2 新旧程度

固定为以下五档：

1. 全新未使用；
2. 几乎全新；
3. 明显使用痕迹；
4. 外观较旧，功能正常；
5. 部分功能异常。

选择“部分功能异常”时，表单额外显示必填的故障说明字段；商品卡片和详情页显示醒目的异常标签，详情页完整展示故障说明。

### 3.3 免费赠送

参考单价允许为 0。零元商品统一显示“免费赠送”，仍然经过聊天、预约、库存占用和结果确认流程，不增加新的信息类型。

### 3.4 商品图片

- 至少 1 张、最多 6 张；第一张作为封面。
- 发布前支持预览、删除和调整顺序。
- 客户端以 2 MB 为自动压缩目标，超过目标时逐档尝试质量 80/60/40 并保留最小结果；单张最终上传文件不得超过 5 MB。小图不重复压缩；无法压缩时仅允许不超过 5 MB 的原图上传。（2026-10-01 根据手机拍照反馈调整）
- 只接受 JPEG、PNG 或 WebP，不支持视频。
- 商品下架或交易结束时不立即删除云存储图片，避免历史聊天和交易快照失效。

### 3.5 编辑、下架与删除

- 卖家可以修改标题、描述、图片、分类、参考价格、新旧程度和校区。
- 总库存不得调低到“已预约数量 + 已售数量”以下。
- 已生成的交易清单继续使用生成时的商品快照，不随商品修改。
- 下架后商品不再出现在发现或搜索结果中，但已成立的预约继续有效。
- 存在预约或历史交易的商品不能物理删除，只能下架并保留记录。

## 4. 发现与商品详情

### 4.1 发现页

- 使用两列商品卡片网格，仅展示可预约的出售商品。
- 支持下拉刷新和分页加载。
- 已完善资料的用户默认选择常驻校区；匿名或资料未完善用户默认选择“全部校区”。
- 顶部可切换全部、西土城、沙河、海南；每个范围内按发布时间倒序。
- 用户手动切换后只在本次小程序使用期间保留，不写入云端，也不改变常驻校区。
- 卡片显示封面、标题、价格或“免费赠送”、校区、新旧程度以及必要的异常标签。

阶段 1 不实现出售/求购混合瀑布流、关键词搜索、复杂分类筛选或推荐算法。

### 4.2 无可预约库存

- `availableQuantity = 0` 的商品从发现、搜索和分类结果中隐藏。
- 新买家不能再建立会话或发起交易清单。
- 已有聊天、预约、历史交易以及卖家的“我的发布”仍可打开商品详情。
- 只是被预约完时显示“已预约”；全部库存实际售出后显示“已售罄”。
- 预约取消或失败释放库存后，商品自动恢复展示。

### 4.3 商品详情操作

- 普通买家看到“联系卖家”，进入该商品对应会话。
- 交易清单只能从聊天页发起，不在商品详情页直接发起。
- 卖家查看自己的商品时显示“编辑商品”和“下架商品”，不显示“联系卖家”。

## 5. 文字聊天

### 5.1 会话唯一性

每个“商品 + 买家 + 卖家”对应一个会话：

- 同一买家重复联系同一商品时复用原会话；
- 咨询另一件商品时建立新会话；
- 商品下架或售罄后保留历史聊天；
- 存在预约或历史交易时仍可从消息与交易记录进入会话。

### 5.2 消息能力

- 阶段 1 只支持文字消息与系统消息。
- 文字去除首尾空白后不能为空，单条最多 500 个字符。
- 普通网址按纯文本显示，不自动生成可点击链接。
- 客户端防止连续点击重复发送；云函数通过请求 ID 保证同一请求幂等。
- 暂不支持图片、商品卡片、富文本、链接预览、表情包、撤回、删除、引用回复、输入状态和对方已读回执。

### 5.3 会话与未读状态

- 会话列表显示商品、对方、最后一条消息和时间。
- 每个会话显示当前用户的未读数量。
- 底部“消息”显示所有会话未读总数。
- 用户进入会话后，将对方消息和系统消息标记为已读。

## 6. 交易清单

### 6.1 发起与确认

- 只有买家可以从聊天页发起交易清单。
- 清单包含商品快照、数量、约定时间、校区和具体地点。
- 商品快照至少包含商品 ID、标题、封面、参考单价和生成时间。
- 平台不记录或裁定最终线下成交金额。
- 卖家只能整体确认或拒绝；修改数量、时间或地点时，由买家撤回原清单后重新发起。
- 同一会话同一时间只能存在一张未结束清单。
- 不同买家可以同时发起待确认清单，只有卖家确认时才占用库存。

### 6.2 时间和地点

- 约定时间至少晚于当前时间 10 分钟，最远为未来 14 天。
- 地点由“校区 + 具体地点”组成。
- 校区默认商品所属校区，可切换至其他北邮校区。
- 具体地点必填，2～50 个字符。
- 交易结果按钮仅在约定时间到达后开放。

### 6.3 取消规则

- 卖家确认前：买家可以撤回，卖家可以拒绝，不占用库存。
- 卖家确认后、约定时间前：买卖双方均可取消，必须选择原因，并立即释放库存。
- 约定时间到达后：不允许普通取消，只能提交交易成功或交易失败结果。
- 所有撤回、拒绝和取消均保留操作者、原因与时间记录。

### 6.4 状态机

用户可见状态：

`待卖家确认 → 待交接 → 已完成 / 已失败 / 异常 / 已取消`

- 卖家确认后进入“待交接”并占用库存。
- 约定时间到达后仍显示“待交接”，同时开放结果操作。
- 双方均确认成功：交易完成，预约库存转为已售库存。
- 任一方先确认失败：交易立即失败并释放库存。
- 对方随后也确认失败：保持失败。
- 对方随后确认成功：改为异常；已释放库存不重新占用。
- 结果一经提交不可自行修改，只能保留事件记录。
- 阶段 1 不做平台仲裁、自动成功或自动失败。

### 6.5 系统消息

发起清单、卖家确认或拒绝、撤回、取消、结果提交、完成、失败和异常均在对应会话内生成不可编辑的系统消息。系统消息计入未读数量。

阶段 1 不请求微信订阅消息授权，也不建设独立通知中心。

## 7. 库存模型与并发

商品库存保存：

- `totalQuantity`：发布总数量；
- `availableQuantity`：当前可预约数量；
- `reservedQuantity`：已预约数量；
- `soldQuantity`：已售数量。

任何时刻必须满足：

`totalQuantity = availableQuantity + reservedQuantity + soldQuantity`

并发规则：

- 买家发起清单时不占用库存。
- 卖家确认时重新读取商品与交易状态。
- 只有商品仍在售、交易仍待确认且可预约库存充足时才能确认。
- 库存检查、库存占用、交易状态、事件流水、库存流水和系统消息在同一可信操作中完成；库存与交易核心更新使用云数据库事务。
- 多位买家同时确认时，最先成功提交事务的预约生效；库存不足的请求失败并显示明确提示。
- 重复确认、取消、失败或完成不得重复占用、释放或扣减库存。

## 8. “我的”页面

阶段 1 包含：

- 个人资料入口；
- 我的发布：在售、已下架、已预约完、已售罄；
- 我的交易：买家和卖家视角，显示待卖家确认、待交接、已完成、已失败、异常和已取消；
- 待处理数量提示，例如待卖家确认和待交接。

阶段 1 不包含收藏、浏览历史、信用评价和完整账号设置。

## 9. 技术架构

### 9.1 云函数边界

采用按业务域拆分的云函数，不建立单一 `marketApi`：

- 商品域：创建、更新、上下架、列表和详情；
- 会话域：建立或复用会话、会话列表；
- 消息域：发送、分页读取、标记已读；
- 交易域：发起、撤回、确认、拒绝、取消和提交结果。

公共身份、稳定错误响应、校验与幂等逻辑可以复用，但商品、消息和交易的权限边界保持独立。

### 9.2 新增集合

| 集合 | 作用 | 主要关系 |
| --- | --- | --- |
| `posts` | 出售商品与库存 | `ownerId`、`schoolId`、`campusId` |
| `conversations` | 商品会话与未读摘要 | `postId`、`buyerId`、`sellerId` |
| `messages` | 文字和系统消息 | `conversationId`、`senderId` |
| `transactions` | 交易清单与双方结果 | `conversationId`、`postId`、买卖双方 |
| `transaction_events` | 交易状态审计流水 | `transactionId`、操作者 |
| `inventory_movements` | 库存变化流水 | `postId`、`transactionId` |

金额以“分”的整数存储。商品、交易、消息和流水不做物理删除，客户端不能直接修改库存或交易状态。

### 9.3 权限

- 所有写操作由云函数从可信微信上下文获取 OpenID，再解析平台用户身份。
- 用户只能读取与自己有关的会话、消息和交易。
- 卖家只能管理自己的商品。
- 商品公开列表和详情只能返回允许公开的字段。
- 客户端提交的用户 ID、库存数、价格快照和状态均不可信，云函数必须重新读取并校验。

## 10. 错误处理

云函数继续使用 `{ ok, data?, error? }` 稳定响应结构。用户错误提示包括但不限于：

- 商品库存不足，请重新选择数量；
- 该交易已被处理，请刷新后查看；
- 约定时间尚未到达；
- 商品已经下架；
- 当前已有一张进行中的交易清单；
- 你没有权限执行此操作。

客户端在请求失败后保留用户已经填写的发布、消息或交易清单内容，允许修正或重试。

## 11. 测试与验收

### 11.1 自动化测试

至少覆盖：

- 商品字段、图片、价格、库存和新旧程度校验；
- 免费赠送显示；
- 部分功能异常必须说明故障；
- 商品编辑的库存下限；
- 会话唯一性、消息长度、请求幂等和未读计数；
- 只有买家可以发起清单；
- 时间、地点和同会话单一进行中清单限制；
- 原子库存占用、释放和售出；
- 完成、失败、异常、取消及非法状态迁移；
- 越权读取与写入；
- 并发确认不超卖。

### 11.2 双账号人工验收

1. 卖家发布包含图片和库存的商品；
2. 买家从默认校区发现商品并进入详情；
3. 买家联系卖家并收发文字消息；
4. 未读数量和底部角标正确变化；
5. 买家发起交易清单，卖家确认；
6. 库存减少，库存为零时商品从发现页隐藏；
7. 约定时间前取消，验证库存恢复；
8. 重新发起并到达约定时间，双方确认成功；
9. 验证预约库存转为已售库存；
10. 分别验证交易失败和双方结果冲突；
11. 使用多个请求验证库存不会超卖；
12. 检查我的发布、我的交易和会话系统消息。

## 12. 阶段外范围

阶段 1 不实现：

- 求购和服务发布；
- 图片消息及商品卡片消息；
- 微信订阅消息和独立通知中心；
- 自动超时成功或失败；
- 支付、退款、评价和平台仲裁；
- 收藏、浏览历史和复杂搜索推荐；
- 管理后台。

以上能力只能在后续阶段重新确认后实施。
