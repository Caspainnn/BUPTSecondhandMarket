# 邮子二手铺阶段 0：项目骨架与数据基础设计

## 1. 目标与范围

阶段 0 建立一个可持续开发、可在微信开发者工具和真机运行的微信原生小程序，并完成“匿名浏览—微信身份建档—完善资料—云端持久化”的最小闭环。

本阶段只实现项目骨架、用户资料、学校与校区基础数据，以及供后续业务复用的登录守卫。商品、求购、聊天、交易、库存和通知只记录后续关系与索引方向，不创建空业务模块或提前实现页面。

## 3. 技术方案

- 客户端使用微信原生小程序，不引入跨端框架或第三方 UI 组件库。
- 数据使用微信云数据库，头像使用微信云存储，可信写操作使用微信云函数。
- 首页允许匿名访问；发布、聊天和预约等后续受保护操作统一经过登录守卫。
- 首次需要身份的操作触发用户建档；资料未完整时跳转到资料完善页。
- 阶段 0 的首页只提供项目基础信息、登录状态和守卫演示入口，不实现商品流。

## 4. 页面与组件

### 4.1 首页

- 允许匿名进入。
- 展示品牌基础信息和当前登录状态。
- 提供一个受保护操作演示入口，用于验证登录守卫；不承载真实业务。

### 4.2 我的

- 调用登录能力获取当前用户资料摘要。
- 展示头像、昵称、常驻校区及资料完整状态。
- 提供进入资料编辑页的入口。

### 4.3 资料编辑

- 用户主动选择头像、填写昵称、选择常驻校区。
- 头像、昵称和常驻校区均为必填。
- 保存失败时保留当前输入并显示可理解的错误；不得把失败误报为成功。

## 5. 云函数与数据流

### 5.1 `login`

1. 从云函数可信上下文取得微信 OpenID。
2. 按 OpenID 查询用户记录。
3. 首次访问时创建资料未完善的用户记录；已有记录则读取资料摘要。
4. 仅向当前调用者返回其自己的必要资料。

### 5.2 `updateProfile`

1. 从可信上下文取得 OpenID，不接受客户端传入的用户身份。
2. 校验昵称、头像文件 ID 和校区 ID。
3. 校区必须存在、处于启用状态且属于北京邮电大学。
4. 全部校验通过后一次性更新资料和 `profileCompleted`；失败时不留下半完成状态。

### 5.3 头像上传

1. 用户通过微信原生能力选择头像。
2. 客户端上传至当前云环境的云存储。
3. 上传成功后把云文件 ID 交给 `updateProfile` 保存。
4. 上传失败时允许重试，不更新用户资料。

## 6. 数据结构

### 6.1 `users`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_openid` | string | 微信用户身份，仅由可信云端写入 |
| `nickname` | string | 用户主动填写的昵称 |
| `avatarFileId` | string | 云存储头像文件 ID |
| `schoolId` | string | 固定关联北京邮电大学 |
| `campusId` | string | 常驻校区 ID |
| `profileCompleted` | boolean | 必填资料是否完整 |
| `status` | string | `active` 或 `disabled` |
| `createdAt` | date | 云端创建时间 |
| `updatedAt` | date | 云端更新时间 |

`_openid` 建立唯一索引，避免同一微信身份产生重复用户记录。

### 6.2 `schools`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schoolId` | string | 稳定业务 ID |
| `name` | string | 学校名称 |
| `enabled` | boolean | 是否启用 |

`schoolId` 建立唯一索引。

### 6.3 `campuses`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `campusId` | string | 稳定业务 ID |
| `schoolId` | string | 所属学校 ID |
| `name` | string | 校区名称 |
| `enabled` | boolean | 是否启用 |
| `sortOrder` | number | 展示顺序 |

`campusId` 建立唯一索引；`schoolId + enabled + sortOrder` 建立查询索引。

## 7. 权限与校验

- `schools` 和 `campuses` 允许客户端只读，禁止客户端写入。
- `users` 禁止客户端直接新增或更新，所有写操作必须经过云函数。
- 用户只能获得自己的完整资料。
- 昵称提交前去除首尾空格，空昵称不通过校验；长度限制采用客户端提示与云函数强校验双保险。
- 校区值不能依赖客户端选项，云函数必须再次查询并校验。
- 日志只记录排障所需的操作类型和错误信息，不记录密钥或完整隐私数据。

## 8. 错误处理

- 云函数返回稳定的业务错误码和用户可理解的消息。
- 网络错误、云函数错误和头像上传错误均提供重试路径。
- 客户端只在云端明确成功后更新成功状态。
- 重复调用登录不能创建重复用户；资料更新采用当前用户单记录覆盖，保证幂等。
- 停用用户不能更新资料，并获得明确提示。

## 9. 验收标准

1. 新用户可以匿名进入首页。
2. 点击受保护入口时，未建档用户完成微信身份建档；资料不完整时进入资料页。
3. 头像、昵称和常驻校区均为必填。
4. 西土城、沙河和海南三个校区均可选择并正确保存。
5. 退出页面、重新进入或真机重启后，资料仍可从云端读取。
6. 客户端伪造不存在或停用的校区 ID 时，云函数拒绝更新。
7. 两个微信测试账号形成相互独立的用户记录，不会互相读取或覆盖。
8. 云开发控制台能够查看正确的用户、学校和校区记录。
9. 本地自测和真机验收分别记录；未完成真机验证前不得宣称阶段完成。

## 10. 人工配置与限制

- 用户需要在微信开发者工具中导入项目，并确认 AppID 和云环境。
- 用户需要在云开发控制台创建集合、配置权限与索引，并部署云函数；具体步骤在实施和验收文档中列出。
- 当前个人主体可选类目与完整的 UGC 二手交易功能不匹配。阶段 0 可以开发和测试，但正式提审前必须解决主体与服务类目问题。
- 微信开发者工具模拟器通过不等于真机通过，头像选择、微信身份和云环境必须真机复验。
